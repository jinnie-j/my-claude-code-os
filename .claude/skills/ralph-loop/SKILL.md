# 랄프 루프 (ralph-loop)

**측정 가능한 목표**를 향해 "작은 진전 → 측정 → 반복"을 자동으로 도는 오케스트레이터 스킬이다. 각 이터레이션은 **매번 새로 스폰되는 `ralph-worker`**(독립 컨텍스트)가 실행하고, 이 스킬은 **지표를 직접 재서** 계속할지 멈출지 판정한다.

```
목표 G + 지표 M 받음
 └─ 반복(최대 N회):
     ① M 측정(baseline)  → ② ralph-worker 스폰(독립 컨텍스트)로 "다음 한 가지" 실행
     → ③ M 재측정  → ④ 종료 판정(목표달성/개선없음/최대회차)  → ⑤ 체크포인트 커밋 → ①
```

> 💡 **왜 이터레이션마다 새 워커인가?** 서브에이전트는 매 호출이 격리된 새 컨텍스트다. 그래서 ① 회차가 쌓여도 워커 토큰이 안 불고, ② 앞 회차의 혼동·환각이 누적되지 않으며, ③ 기억을 대화가 아니라 **파일(PROGRESS.md)**에 남기도록 강제된다. 이게 랄프의 본질이다.
>
> 💡 **왜 측정은 스킬(오케스트레이터)이 하나?** 일한 주체가 자기 성과를 자평하면 편향된다. **워커는 실행, 오케스트레이터는 지표로 판정** — 만드는 자와 재는 자를 분리한다(이 OS의 일관된 원칙).

## 사용 시점
- "랄프 루프 돌려줘", "○○ 될 때까지 반복해줘"처럼 **작은 개선을 여러 번 반복해야 닿는, 완료를 숫자로 잴 수 있는** 목표일 때.
- 안 맞는 경우: "완료"가 모호하거나(취향·설계 판단), 한 번의 판단이 핵심인 일 → `feature-dev` 한 번이 낫다.

## 파라미터 (없으면 사용자에게 먼저 묻는다)
- **goal** (목표): 무엇이 되면 끝인지. 예) "실패 테스트를 0으로", "린트 경고 0".
- **metric** (지표): 진전을 재는 기준.
  - `measure`: 숫자나 pass/fail을 출력하는 **셸 명령**. 예) `python3 -m unittest discover -s tests 2>&1 | tail -1`
  - `target`: 종료 조건. 예) `"실패 0"`, `">= 90"`, `"green"`
  - `direction`: 개선 방향 `min`(줄일수록 좋음) 또는 `max`(늘릴수록 좋음)
- **max_iterations** (선택, 기본 8): 안전 상한.

> 💡 지표는 **반드시 프로그램으로 측정 가능**해야 한다. 못 재는 목표면 이 스킬을 쓰지 말고 사용자에게 알린다.

## 절차

### 0. 준비
- 요구가 모호하거나 지표가 측정 불가면 **시작 전에 사용자에게 확인**한다.
- **반드시 되돌릴 수 있는 브랜치**에서 돈다(무인 반복이므로). main이면 먼저 작업 브랜치를 만든다.
- `.claude/ralph/GOAL.md`(목표·지표 원문)와 `.claude/ralph/PROGRESS.md`(할일·회차 로그)를 만든다(없으면).

### 1. 루프 (아래를 목표 달성 또는 종료조건까지 반복)
1. **baseline 측정** — `metric.measure`를 실행해 현재 값을 얻는다. 실행 실패/파싱 불가면 **멈추고 사용자에게 보고**(지표가 깨졌다는 신호).
2. **이미 목표 달성이면** 루프에 들어가지 않고 종료로 간다.
3. **ralph-worker 스폰(독립 컨텍스트)** — 프롬프트에 **{goal, metric, `.claude/ralph/GOAL.md`·`PROGRESS.md` 경로, 직전 회차 요약}**을 담아 넘긴다. (워커는 대화를 공유하지 않으므로 명시 전달.) 워커는 "다음 한 가지"를 실행하고 PROGRESS.md를 갱신한다.
   - 워커가 "무거운 기능 개발이 필요하다"고 보고하면, 그 회차는 대신 `feature-dev`로 돌린다.
4. **재측정** — `metric.measure`를 다시 실행해 새 값을 얻고, `direction` 기준으로 **개선분**을 계산한다.
5. **체크포인트 커밋** — 이번 회차 변경을 커밋한다(회차별 되돌림 지점). 커밋 메시지에 회차·지표값을 남긴다.
6. **종료 판정 → 아니면 1로.**

### 2. 종료 조건 (아래 중 하나라도)
- **목표 달성**: 지표가 `target`을 만족. → 성공 종료.
- **개선 없음(dry)**: **연속 2회** 지표가 나아지지 않음(또는 악화). → 멈추고 "정체" 보고.
- **최대 회차 도달**(`max_iterations`). → 멈추고 남은 것 보고.
- **지표 측정 실패** 또는 **위험 작업 필요**. → 즉시 멈추고 사용자 확인.

### 3. 최종 보고
- 지표 궤적(회차별 값), 목표 달성 여부, 총 회차·커밋, `PROGRESS.md`의 남은 `- [ ]` 항목을 정리해 보고한다.

## 가드레일 (반드시)
- **종료 조건 없는 반복 금지** — 목표 달성/dry 2회/최대 회차 중 하나에서 **반드시** 멈춘다.
- **지표 꼼수 차단** — 워커가 지표를 속이려 테스트를 삭제·무력화하지 않는지 본다. 필요하면 불변식(예: "테스트 수가 줄지 않는다")을 회차마다 함께 점검한다.
- **되돌림 보장** — 브랜치에서, 회차마다 커밋. 잘못되면 그 회차만 롤백.
- **오케스트레이터 컨텍스트 절약** — 워커 반환은 짧게 유지하고, 상세는 PROGRESS.md에 남긴다.
- 위험·범위 초과 변경이 필요하면 멈추고 사용자에게 묻는다.
